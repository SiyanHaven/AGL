# AGL 编译器流水线接口契约 v0.1

> **这份文档的作用**：多个 AI 并行开发时，各模块之间的**数据结构**必须先固定。谁改了这里，其他人的代码全部要跟着改。
> **纪律**：本文件由项目主控（人）冻结。任何修改须主控批准，且过全量用例回归。

---

## 一、流水线总览

```
  .agl 源码
      │
      ▼  M1 词法分析器（compiler/lexer）
   Token 流          ← 接口见 §二
      │
      ▼  M2 语法分析器（compiler/parser）
   AST               ← 接口见 §三（阶段 1 与 IR 同构）
      │
      ▼  M4 IR 构建 + 降级 + 优化（compiler/ir）
   IR（.agl.ir）      ← 接口见 spec/ir-schema.json
      │
      ├──▶ M5 后端 A：转译 Python（compiler/backend_py）
      │
      └──▶ aglc --摘要 / 错误回译 / 契约（§4.5）
```

**并行的前提**：M1 只认 `spec/keywords.toml`；M2 只认 Token 结构；M4 只认 AST 结构；M5 只认 IR schema。
**任何模块都不得直接依赖另一个模块的内部实现**，只依赖本文档定义的数据结构。

## 二、Token 结构（M1 输出 / M2 输入）

### 2.1 定义

```python
from dataclasses import dataclass
from typing import Literal

TokenKind = Literal[
    "KEYWORD",    # 关键字（中英皆可，看 canonical）
    "IDENT",      # 标识符（原文可能是中文或英文）
    "INT",        # 整数字面量
    "FLOAT",      # 浮点字面量
    "STRING",     # 字符串字面量（保留原始内容，含引号内的空格）
    "OP",         # 运算符 / 分隔符（+ - * / ( ) { } [ ] , : -> 等）
    "NEWLINE",    # 换行（用于终止语句，若采用换行敏感语法）
    "COMMENT",    # 注释（保留，供 §4.5 意图行提取）
    "EOF",        # 结束
]

@dataclass(frozen=True)
class Token:
    kind: TokenKind
    text: str        # 源码原文，逐字保留（用于错误提示"你写的是这个"）
    canonical: str   # 规范化形式（**语义判断只看这个**）
    line: int        # 起始行，1-based
    col: int         # 起始列，0-based
    end_line: int
    end_col: int
    file: str
```

### 2.2 `canonical` 字段（这一条是全设计的关键）

**中英双分支必须产出完全相同的 `canonical`**，这样 M2 语法分析器只写一套，不用管源码是中文还是英文。

| 源码（中文分支） | 源码（英文分支） | `kind` | `text` | `canonical` |
|---|---|---|---|---|
| `如果` | `if` | KEYWORD | 各自原文 | **`if`** |
| `函数` | `fn` | KEYWORD | 各自原文 | **`fn`** |
| `网络` | `Net` | KEYWORD | 各自原文 | **`Net`** |
| `等于` | `==` | OP | 各自原文 | **`==`** |
| `并且` | `&&` | OP | 各自原文 | **`&&`** |
| `核对账目` | `reconcile` | IDENT | 各自原文 | **各自原文**（标识符不规范化、不翻译，§3.17） |

> **规范化的边界**：只规范化**关键字与运算符**（查 `keywords.toml` → 取对应英文规范名）。
> **标识符、字符串、注释一律不规范化**，`canonical` 等于 `text` 原样。

### 2.3 错误约定

- 未知字符 / 未闭合字符串 / 非法数字格式 → 报 `AGL-E-01xx`（见 `diagnostics.md`），**必须带行列号**；
- 首行缺 `#语言=` / `#lang=` → `AGL-E-0101`，立即终止（无法确定用哪套关键字表）；
- 中英混用（同一文件出现另一分支的关键字）→ `AGL-E-0102`，**这是硬错误**（§3.1 禁混用）。

### 2.4 M1 验收标准

- 中文、英文各 20 个用例，Token 序列（含行列）逐项与 golden file 一致；
- 中英等价用例的 `canonical` 序列**完全相同**（这是最重要的一条）；
- 缺语言声明、混用、未闭合字符串三类错误全部正确报出。

## 三、AST 结构（M2 输出 / M4 输入）

### 3.1 设计决定：阶段 1 AST 与 IR 同构

为降低多模块协作成本，**阶段 1 的 AST 直接采用 `spec/ir-schema.json` 的结构**，唯一差别：

- AST 允许保留"语法糖"（如 `匹配 match` 阶段 1 未落地时报 AGL-E-0503；`异步 async` 阶段 2 起已是真异步运行时，不是标记）；
- AST 的所有 `type` / `op` / `effects` 字段**已按 canonical 规范形式填写**（见 §2.2）；
- AST 的每个节点**必须已带完整 `span`**（M2 是 span 的生成者，M4 只是搬运，**不允许 M4 补 span**）。

> 为什么这样定：如果让 M2 输出一套结构、M4 再映射成另一套，就多出一个"两套结构对不上"的故障面。阶段 1 直接同构，M4 的职责收窄为 **降级 + 优化 + 校验**，边界更清楚。

### 3.2 M4 的明确职责（不含结构转换）

1. **降级**：`匹配` 阶段 1 未实现，编译期报 AGL-E-0503（不静默降级成 if-elif，避免行为悄悄跑偏）；`异步` 阶段 2 起走真异步运行时（任务 / 等待 / 取消 / 回调），不再按同步处理；
2. **优化 Pass**：常量折叠、死代码消除（**必须语义等价**，用用例断言）；
3. **schema 校验**：用 `ir-schema.json` 校验自己产出的 IR，并断言每个节点有 span；
4. **序列化**：输出 `xxx.agl.ir`（JSON，UTF-8，2 空格缩进，`ensure_ascii=False`）。

### 3.3 M2 验收标准

- 语法错误报错信息**准确**：带行号 + 期望什么 + 实际遇到什么（`AGL-E-02xx`）；
- 块配对（`{ }` 括号栈）错误能定位到**开始不匹配的那一行**；
- 中英各 20 个用例的 AST 与 golden file 逐节点相等。

## 四、跨模块通用纪律

| # | 纪律 | 违反后果 |
|---|---|---|
| 1 | **不许硬编码关键字** | 必须从 `spec/keywords.toml` 读，否则双分支必然不同步 |
| 2 | **不许翻译标识符 / 字符串 / 注释** | 直接破坏 §3.17 可逆性，往返校验必挂 |
| 3 | **span 只能由 M2 生成** | M4/M5 补 span 会导致错误回译指错行 |
| 4 | **类型名与效应名一律用规范英文** | 否则双分支 IR 无法逐节点比对 |
| 5 | **错误码只用 `diagnostics.md` 里的** | 临时编的码会让前端和 AI 无法稳定识别 |
| 6 | **改断言先改用例** | golden file 是唯一裁判，改之前先说明为什么 |
