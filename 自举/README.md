# 自举目录：AGL 语言写的 AGL 编译器

**这个目录里的每份 `.agl` 源码，都是用 AGL 语言写的**——不是 Python，不是任何宿主语言。
它们合起来构成一个完整的编译器：读入 `.agl` 源码 → 产出可在自研 VM 上运行的 AGB 字节码。

## 文件清单（谁是谁）

| 文件 | 是什么 | 怎么证明它是 AGL |
|---|---|---|
| `词法器.agl` | 源码 → 记号流（中英关键字、字符串、数字、符号） | 用 `aglc run 自举/词法器.agl` 跑起来，它解析黄金用例，记号数与种子词法器逐字一致 |
| `语法分析器.agl` | 记号流 → AST（全部语法：如果/当/循环/匹配/尝试/工具声明/接口/依赖…） | 它能解析**它自己的源码**（自解析）；doctor 第 27 项断言 |
| `中间表示.agl` | AST → 中间表示 IR（编译器的核心语义层） | 它生成的 IR 与种子编译器生成的 IR 逐字段一致；doctor 断言 |
| `字节码.agl` | IR → AGB 字节码（常量池 / 指令 / 行号表） | 它生成的字节码在 VM 上跑，输出与 Python 后端逐字一致；doctor 断言 |
| `编译器.agl` | B3 最小闭环演示：只编 `打印` 程序 | 产出 selfhost_hello.agb，VM 执行输出「你好 AGL」 |
| `自举编译器.agl` | **整链入口**：词法→语法→IR→字节码 一次完成 | 见下方"自举闭环" |

## 自举闭环（怎么证明"AGL 能写编译器"）

```bash
aglc bootstrap
```

一条命令做四件事：

1. **种子**（Python 写的 `compiler\`，只当脚手架）把 `自举编译器.agl` 编成 v1；
2. v1 编译 `自举编译器.agl` 自己 → v2；
3. v2 再编译一次 → v3；
4. **断言 v2 与 v3 逐字节相同**（不动点），把 v3 安装到 `build\自举编译器\自举编译器.agb`。

从这一刻起，`aglc build/run` 默认用的就是**这个目录里的 AGL 代码编译出来的编译器**；需要回退 Python 种子时加 `--compiler seed`。
每次安装的 SHA 与耗时记录在 `build\自举编译器\bootstrap_history.log`。

## 与 Python 种子（`compiler\`）的关系

| | `自举\`（本目录） | `compiler\` |
|---|---|---|
| 语言 | **AGL** | Python |
| 角色 | 正式的编译器本体（B6 起可日用） | 引导脚手架 + 静态校验 + 工具链（MCP/LSP/体检） |
| 淘汰计划 | 不断扩覆盖（见 docs/自举路线.md §5e） | 校验与工具链长期保留；"编代码"职责逐步移交 |

规则：本目录的 AGL 源码**禁用「或者」「&&」**（自举解析器只认「或」「并且」）；
改动后必须 `aglc bootstrap` 重建不动点，并跑 `scripts/b8_sweep.py`（70/70）与 `aglc doctor`（27 项）。
