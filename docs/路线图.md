.# AGL 路线图

## 0.53.0 当前状态

- 中文/英文双分支语言与编译器；
- AGL 自举编译器（发布包内为预编译 `.agb`，Python 种子编译器仅作回退）；
- 自研 VM、AGB 字节码、效应声明与工具白名单；
- 模块、异常、匹配、任务、HTTP、FFI；
- MCP 工具服务器；
- 中英双语规范与六个可运行示例。

## 语言定位

AGL 是一门**自举的、面向 AI 生成与人类审查的声明式语言**。它的核心目标不是替代 Python，也不是只做 Python 翻译，而是让 AI 生成的程序在运行前可以回答三个问题：

1. 它会读写哪些文件？
2. 它会访问哪些网络或外部进程？
3. 出错时能不能回到源码文件和行号？

因此，AGL 的长期定位是：

> **AI 生成代码的可审查、可限制执行层。**

自举是工程可信度的一部分，但不是唯一卖点。语言本身仍然是完整的：有词法、语法、类型、效应、模块、IR、字节码、VM、标准库和自举编译器。

## Python 与 AGL 的关系

Python→AGL 只会作为**可选的迁移与审阅桥**存在，不改变 AGL 的语言主体，也不把 AGL 定义成“Python 翻译器”。

这个桥分两种模式：

- **可读转译**：把 Python 代码转成 AGL 风格的可读稿，用于人工审查；不承诺可直接运行。
- **可运行转译**：只覆盖 AGL 已有的语义子集；必须通过 `aglc check`，并用同一组输入对比 Python 与 AGL 的输出。

无法映射的 Python 构造会带行号写入转译报告，不会静默近似。它不进入 AGL 的核心语法，也不要求 AGL 为了兼容 Python 而增加类、继承、装饰器、生成器等构造。

## 升级原则

- 不为“像 Python”而补语法；只补真实项目需要的能力。
- 先闭环运行期安全，再扩生态和语言表面。
- 每个新能力必须配真实模板、文档和可复现验证；不以示例数量代替可用性。
- 自举编译器保持可构建、可对照；Python 种子编译器只作为回退和排障。

## 近期：安全执行闭环

这是当前最重要的升级方向。现有的效应检查主要在编译期，下一步要变成运行期强制。

1. **运行期效应强制**
   - 读写只允许工作目录或显式授权的路径；
   - 网络只允许白名单域名；
   - 外部进程只允许白名单命令；
   - 未声明的效应在运行时直接失败，而不是只给警告。

2. **审计日志与 dry-run**
   - 记录每次文件、网络、进程、FFI 调用；
   - `--dry-run` 只输出执行计划，不产生真实副作用；
   - 人和 AI 可以先审计划，再批准执行。

3. **资源配额**
   - 时间、步数、内存、输出大小、写入量；
   - 长任务和批量任务有明确上限，超限报可定位的错误码。

## 中期：可用性与分发

4. **真实模板**
   - CSV 批量清洗器；
   - 目录规则审计器；
   - SQLite 报表器。
   
   每个模板都要有输入样例、输出、错误处理和一条可复现的运行命令。

5. **标准库硬化**
   - 文件、目录、CSV/JSON、日期、统计、文本、SQLite、日志；
   - 每个公开函数有文档、边界说明和测试；
   - 不追求数量，优先保证常用路径稳定。

6. **便携运行时**
   - 提供不要求用户预装 Python 的便携包或安装器；
   - 保持 `aglc doctor` 5/5 作为安装完成的唯一标准；
   - 不把“装 Python、配 PATH”留给普通用户。

7. **包管理与可复现构建**
   - `agl.toml`、依赖锁定、版本解析；
   - `.agb` 构建可复现、可校验哈希；
   - 标准库与模块来源可验证，避免不可控的外部依赖。

## 长期：语言与工具链

8. **只补目标域需要的语言能力**
   - 结构体方法、简单泛型容器、更完整的错误类型、模块可见性；
   - 类继承、闭包、装饰器、生成器等，只有在真实模板确实需要时才纳入评估；
   - 不以“和 Python 一样”作为语言目标。

9. **MCP 策略执行**
   - 从“暴露工具”升级为“带策略的检查、计划和执行”；
   - 外部 AI 客户端可以完成“写 → check → dry-run → 带策略 run”，不需要直接操作 shell；
   - 返回结构化诊断、审计记录和可复现的运行结果。

10. **Python→AGL 可选桥**
    - 独立的 `aglc from-python` 入口；
    - 输出 `.agl` 与转译报告；
    - 可读转译和可运行转译分开标注，不混淆能力边界。

## 不在当前版本

- 不承诺兼容任意 Python 语法；
- 不把 Web 框架、GUI、移动端或高并发服务作为近期目标；
- 不提供商业 SLA 或私有咨询；
- 不做无审核的任意外部命令执行；
- 不把自举本身当作对外唯一卖点。

## 升级是否成功的标准

1. 一个越权读取工作目录外文件的 AGL 程序，在运行期被拦住并留下审计记录。
2. 外部 AI 客户端能通过 MCP 完成“写 → check → 带策略 run”，不需要 shell。
3. 非程序员能读懂一个 500 行左右的 AGL 工具，并说清它会碰哪些文件和网络。
4. 三个真实模板在干净的 Windows 环境上一条命令跑通。
5. 用户不需要先安装 Python 就能运行便携包。

路线图会随版本调整；具体能力以当前规范、`aglc doctor` 和发布说明为准。
