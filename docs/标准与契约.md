## 0. 三十秒读懂

**AGL 是什么**：一门面向智能体（Agent）的声明式语言，让不懂编程的人也能看懂 AI 要做什么。
**阶段 1 做到什么**：`.agl` 源码 → 检查 → 中间表示（IR）→ Python，能跑，出错能指回源码行号；
标准库可导入；编译器可作为 MCP 工具被 AI 客户端直接调用，也可作为语言服务器让编辑器里
边写边报错、悬停看中英对照、点一下跳到定义。
**阶段 1 不做什么**：不做运行时沙箱、不做权限拦截、不做原生 VM（见 §8）。
**阶段 2 已做什么**：真异步运行时（任务 / 等待 / 取消 / 回调全链路，见 §8.1）。

**五条铁律**（违反任何一条，双分支必然不同步，或者错误回译必然失效）：

| # | 铁律 | 违反后果 |
|---|---|---|
| 1 | 关键字与内置属性只从 `spec/keywords.toml` 读，代码里一个都不许硬编码 | 中英两分支必然漂移 |
| 2 | 标识符 / 字符串 / 注释**永远不翻译、不规范化** | 往返校验必挂，作者的名字被机器篡改 |
| 3 | `span` 只能由 M2（语法分析器）生成 | 错误回译指向错误的行 |
| 4 | 错误码只能用 `spec/diagnostics.md` 里的 | 前端和 AI 无法稳定识别 |
| 5 | 改断言先改用例，`tests/golden` 是唯一裁判 | 改了实现却偷偷改期望 = 假绿 |

## 2. 五份契约

### 2.1 契约一：`spec/keywords.toml`（关键字）

**它是唯一来源。** 词法器、转换器、报错文案全部从这里读，代码里不许出现 `"如果"` 这种字面量。

结构：

```toml
[[keyword]]
zh = "如果"      # 中文分支写法
en = "if"        # 英文分支写法
kind = "stmt"    # decl / stmt / type / effect / literal / builtin / modifier
stage = 1        # 1=阶段1启用；>1 的词法器会报 AGL-E-0106

[[operator]]
zh = "大于"      # 中文用词
en = ">"         # 英文用符号
category = "compare"

[[attribute]]    # 语言内置的只读属性（不是关键字，也不是用户的成员）
zh = "长度"
en = "length"
canonical = "length"
lower_to = "len" # 转译成宿主语言时换成的等价操作
readonly = true
```

**四条硬约束**：
1. `zh` 之间不重复，`en` 之间不重复（`doctor` 会查）；
2. 五个效应标签必须齐全：`IO / Net / model / Time / External`；
3. 运算符必须中英两边都有（否则转换不回去）；
4. 内置属性必须有 `canonical`（等于英文写法）和 `lower_to`，且不许与关键字撞名。

**为什么属性也要进表**：`.长度` 是语言给的读法，不是用户对象的真实成员。
以前它散在词法、语义、后端、转换器四处各写一份，改一处漏三处；
现在只在表里写一次，四处都读它（`doctor` 第 2 项会校验这张表）。

属性的两条行为规则（已实现，改动即违反契约）：
- **转换时跟着分支走**：`.长度` ↔ `.length`，因为它是语言词汇，不是作者的名字；
- **只认紧跟 `.` 的位置**：用户自己叫 `长度` 的变量一个字都不动。

### 2.2 契约二：Token 结构（M1 输出 / M2 输入）

```python
@dataclass(frozen=True)
class Token:
    kind: str        # KEYWORD / IDENT / INT / FLOAT / STRING / OP / NEWLINE / COMMENT / EOF
    text: str        # 源码原文，逐字保留
    canonical: str   # 规范形式，语义判断只看这个
    line: int        # 1-based
    col: int         # 0-based
    end_line: int
    end_col: int     # 结束位置（最后一个字符之后）
    file: str
    # 以下两个是内部字段，不导出到 JSON
    offset: int
    end_offset: int
```

**`canonical` 的规则（这是双分支同构的全部秘密）**：

| 源码（中文） | 源码（英文） | `text` | `canonical` |
|---|---|---|---|
| `如果` | `if` | 各自原文 | `if` |
| `网络` | `Net` | 各自原文 | `Net` |
| `大于` | `>` | 各自原文 | `>` |
| `核对账目` | `reconcile` | 各自原文 | **各自原文（不规范化）** |
| `"你好"` | `"hi"` | 含引号原文 | **原文（不规范化）** |

⇒ **只规范化关键字和运算符；标识符、字符串、注释的 `canonical` 恒等于 `text`。**

### 2.3 契约三：AST / IR

**阶段 1 的 AST 与 IR 同构**，唯一差别是 IR 外面多包一层 `{ir_version, lang, program}`。
理由：少一套结构就少一个"两套对不上"的故障面。

完整定义见 `spec/ir-schema.json`（28 个 `$defs`，当前版本 **v0.2**）。四条要点：

1. **每个语句、表达式、函数、模块必须带 `span`**；`Type` 节点和 `Program` 根节点不带。
2. **类型名、效应名、运算符一律用规范英文**（`Int` / `Net` / `>=`），中文分支也一样。
3. **声明位置的名字保留源码原文**（函数名、参数名、变量名、字段名）。
4. **调用节点用 `target` 区分"调谁的方法"**：`打印(x)` 没有 `target`；
   `工具.打招呼(x)` 的 `target` 是 `工具` 这个表达式。
   少了这个字段，模块调用就退化成"名字是问号的调用"，后端生成不出正确代码。

**内建名的特殊规则**（容易踩，单列）：

| 位置 | 写法 | 例子 |
|---|---|---|
| 声明（函数名） | 保留原文 | `函数 主入口()` → IR `name: "主入口"` |
| 调用（内建函数） | 规范化为英文 | `打印(x)` → IR `name: "print"` |
| 调用（用户函数） | 保留原文 | `相加(1,2)` → IR `name: "相加"` |

为什么：内建函数必须跨分支一致（中英两边调用的是同一个东西）；用户函数名是作者的名字，属于展示层，不许机器篡改。

> 因此**双分支的 IR 不会逐字相同**（`相加` vs `add`）。判断"两份逻辑是否等价"必须用
> `aglc compare`，它做 alpha 等价：把用户标识符按出现顺序编号后比较骨架。

### 2.4 契约四：诊断码（`spec/diagnostics.md`）

```
AGL-E-01xx  词法       AGL-E-02xx  语法       AGL-E-03xx  语义/类型
AGL-E-04xx  效应       AGL-E-05xx  IR/转译    AGL-RT-00xx 运行时
```

**新增错误码只能追加到对应区间末尾，已有码的含义永远不许改。**

每一条诊断（无论编译期还是运行期）的结构化形态固定为：

```json
{
  "code": "AGL-E-0401",
  "severity": "error",
  "message_zh": "函数「主入口」没有声明效应「网络」，但它调用了带该效应的「取数」",
  "agl": { "file": "main.agl", "line": 11, "col": 5, "end_col": 10 },
  "stack": [],
  "effects": ["Net"],
  "cause": null,
  "fix_hints": [{ "kind": "add_effect", "at": "main.agl:8", "suggest": "…" }]
}
```

**`message_zh` 里禁止出现宿主语言术语**（`AttributeError` / `NoneType` / `traceback`）。
宿主原因放 `cause` 字段，那是给排查实现问题的人看的，不是给用户看的。

## 3. 编译流水线：每一步的输入输出

```
source(str)
   │  M1 词法        compiler/lexer
   ▼
list[Token]
   │  M2 语法        compiler/parser          ← span 在这里生成，唯一
   ▼
AST(= IR 结构)
   │  M4 构建        compiler/ir.build
   ▼
IR dict
   │  M3 检查        compiler/checker         ← 名字 / 类型 / 效应
   │  M4 降级        compiler/ir.lower
   │  M4 优化(可选)  compiler/ir.opt           ← 只在 --opt 时跑
   │  M4 校验        compiler/ir.validate_ir
   ▼
IR（合法）
   │  M5 后端        compiler/backend_py
   ▼
(python_code, source_map)
```

| 阶段 | 输入 | 输出 | 不许做什么 |
|---|---|---|---|
| M1 | 源码字符串 | `list[Token]` | 不许判断语法 |
| M2 | Token 流 | AST | 不许补类型、不许翻译标识符 |
| M3 | IR | `list[Diagnostic]` | 不许修改 IR |
| M4 | AST → IR | 合法 IR | **不许补 span**、不许偷偷开优化 |
| M5 | IR | Python + 源映射 | 不许改变语义 |

### 3.1 行号对齐（可读性闭环的技术核心）

M5 生成 Python 时，**按 AGL 语句的 `span.line` 写到同一物理行号**：

```
AGL 第 5 行   函数 相加(甲: 整数, 乙: 整数) -> 整数 {
Python 第 5 行  def 相加(甲, 乙):

AGL 第 12 行  } 否则 {
Python 第 12 行   else:
```

现在 **100% 对齐**（`doctor` 会统计，且低一行就判红），所以运行期拿到 Python 行号就等于拿到 AGL 行号。
万一出现无法对齐的情况，由 `source_map` 兜底：`{python_line: agl_line}`，回译**只认它**。

**一行 AGL 压不进一行 Python 时怎么办** —— 回调块是最难的一处：

| AGL 写法 | Python 落法 | 行号 |
|---|---|---|
| 多行回调块：`当任务完成(甲, x: 文本) {` 换行写两句，再换行 `}` | 块首→`async def`，块内按时各自的行号，`}`→注册语句 | 天然对齐 |
| 单行回调块 + 后面跟着简单语句 | 回调压成 `async def cb(x): 语句`（Python 允许 def 后接简单语句），注册语句用 `;` 挂到下一个语句的行首 | 对齐 |
| 单行回调块 + 后面跟着复合语句（`如果` / `循环`） | 同上压缩，但没有位置挂 `;`，注册语句只能独占一行 | **顺延 1 行** |
| 单行回调块作为块最后一句 | 压缩后，注册语句落在 `}` 那一带 | 对齐 |

最后那种顺延一行是 Python 语法的边界（`:` 后面不能接分号），不是没做。
曾经这条路径会让后续每条语句都顺延 2 行，体检因此给过 95% 的容忍基线 ——
基线一开，"反正只差几行"就成了常态，所以现在把它钉成硬门槛。

`aglc run` 的运行时错误因此能做到：

```
程序在「除以」停止：rt_divzero.agl 第 5 行

✗ AGL-RT-0010  rt_divzero.agl 第 5 行
    5 |   返回 甲 / 乙
      | ^
    问题  不能除以零
    原因  ZeroDivisionError: division by zero
    建议  检查除数是否可能为 0；先判断再除
    AGL 调用栈
      主入口()  rt_divzero.agl:9
      除以()    rt_divzero.agl:5
```

### 3.2 模块导入（跨文件）

**规则一句话：模块名就是文件名，`导入 工具` 找同目录的 `工具.agl`。**

```agl
#语言=中文
// 工具.agl —— 只有带「导出」的函数对外可见
模块 工具

导出 函数 打招呼(名字: 文本) -> 文本 {
  返回 "你好，" + 名字
}

函数 内部计数(数: 整数) -> 整数 {   // 没有「导出」= 私有
  返回 数 + 1
}
```

```agl
#语言=中文
// 主程序.agl
导入 工具

函数 主入口() {
  打印(工具.打招呼("世界"))      // 调用写「模块名.函数名」
}
```

**查找顺序（只有两级，没有第三级）**：

```
导入 数学
  ① 同目录 数学.agl            ← 有就用，用户文件永远优先
  ② 项目 agl.toml 的 [dependencies] 里声明过，且 stdlib/数学.agl 存在 → 用标准库
  ③ 都没有 → AGL-E-0601，并告诉你该在哪一行补什么
```

项目根 = 从入口文件往上找到的第一个 `agl.toml`；没有配置文件就等于「没有依赖可声明」，
标准库不可用（这是有意的：不写就看不出这个项目用了什么）。

**工程配置读坏了一定报错，不许静默当"没依赖"**：

| 情况 | 报什么 |
|---|---|
| `agl.toml` 不是合法 TOML（最常见：中文键没加引号） | `AGL-E-0605`，指向配置文件本身的行号 |

```toml
[dependencies]
"数学" = "0.1.0"      # ✅ 中文键必须加引号：TOML 的裸键只允许 ASCII
数学 = "0.1.0"        # ❌ 直接报 0605
math = "0.1.0"        # ✅ 英文模块名可以裸写
```

四条硬规则：

| 规则 | 违反时 |
|---|---|
| 模块名 = 文件名（去掉 `.agl`）；同目录优先，其次标准库 | `AGL-E-0601` 找不到模块，报错给出期望的完整文件名 + 该补的那一行 |
| 禁止循环导入 | `AGL-E-0602`，报错给出环路 `甲 → 乙 → 甲` |
| 没写 `导出` 的函数 / 类型 / 常量是私有的 | `AGL-E-0603`，报错告诉你去哪个文件加标记 |
| 模块里没有这个名字 | `AGL-E-0604` |

**跨模块也能用结构体和常量**（`导出 类型` / `导出 常量`）：

```agl
// 资料库.agl
导出 类型 客户 {
  编号: 整数
  名字: 文本
}
导出 常量 默认编号 = 0

// 主程序.agl
导入 资料库

变量 甲: 资料库.客户 = 资料库.客户(编号: 资料库.默认编号, 名字: "甲")
```

规则：

* 类型和常量都必须带 `导出`，否则外部不可见（`AGL-E-0603`）；
* 导入方用「模块名.类型名」做注解、用「模块名.类型名(字段: 值, …)」构造，
  字段是否齐全、类型对不对，都按被导入方的声明校验；
* `导入 资料库 作为 L` 之后写 `L.客户` / `L.默认编号` 等价；
* 模块名按文件名原文取，**关键字也能当模块名**（`导入 模型` 合法），
  否则一个叫 `模型.agl` 的文件永远无法被导入。

**生成的宿主模块名一律加前缀 `_agl_`（这条曾经踩过坑）**：

```agl
导入 math          // 英文分支里给模块起名叫 math 很自然
```

如果不加前缀，生成的 `math.py` 会被宿主语言自带的 `math` 顶掉，
运行时报「这个模块没有 `abs` 这个成员」—— 而代码本身是对的。
所以规则是**固定加前缀**，不是"只在冲突时加"：按冲突临时决定会让同一份代码
在不同宿主版本上跑出不同结果。转译产物里看到 `_agl_math` 属正常，不要去改。

**编译顺序**：先编译依赖，再用它们的导出表校验入口文件。
所以依赖里出错，报错指向**依赖文件本身**，不会一律甩给入口文件。

**跨模块运行期错误同样能指回源头**：

```
程序在「危险除法」停止：崩溃库.agl 第 5 行

✗ AGL-RT-0010  崩溃库.agl 第 5 行
    5 |   返回 甲 / 乙
    问题  不能除以零
    AGL 调用栈
      主入口()   rt_cross.agl:7
      危险除法()  崩溃库.agl:5
```

> **实现上的一个坑（已修，别再踩）**：Python 按模块名永久缓存，
> 同一个进程里连续运行两个目录下的同名模块，第二次会拿到上一次的旧代码。
> `run_result` 结束时必须把本次导入的模块从 `sys.modules` 里清掉。

### 3.3 标准库（`stdlib/`）

**用 AGL 自己写，纯函数、零效应。** 不调宿主语言的任何东西，所以：

| 模块 | 内容 |
|---|---|
| `数学` / `math` | `绝对值` `取最大` `取最小` `平方` `是负数` |
| `列表工具` / `list_util` | `求和` `最大值` `最小值` `平均值` `包含` |

用法三步：`agl.toml` 里声明 → `导入 数学` → `数学.绝对值(-3)`。

**为什么阶段 1 的标准库这么小**（如实说明，不是偷懒）：

- 语言还没有追加 / 切片 / 文本切分能力，标准库就算写了也用不了 ——
  这些要等 FFI 或内建映射，属阶段 2；
- 模块名就是文件名，而模块名不翻译，所以中英各一份文件、内容等价，
  `doctor` 第 14 项会比它们的结构等价性；
- 空列表上取 `最大值` / `平均值` 会**如实报错**（越界 / 除零），
  语言不替你返回 0 把错误藏起来。调用前先用 `.长度` 判断。

**版本号分两层**：源码 `依赖` 块里的版本会校验语义化格式；`agl.toml [dependencies]`
里的版本目前仍只作记录，标准库还没有版本化。两层对齐与锁定见 §3.5 与 §8.2。

### 3.4 接口契约（`接口` / `interface`）

**一句话：接口只写签名，编译器保证同文件里有签名完全一致的实现。**

```agl
#语言=中文
接口 支付 {
  函数 付款(金额: 整数) -> 结果<文本>
  函数 查账(单号: 文本) -> 整数
}

函数 付款(金额: 整数) -> 结果<文本> {
  返回 成功("已付")
}

函数 查账(单号: 文本) -> 整数 {
  返回 1
}
```

四条规则：

| 规则 | 违反时 |
|---|---|
| 接口体里只能写函数签名，不能写函数体 | `AGL-E-0319`，提示把实现写到接口外面 |
| 同一个接口里不能出现两条同名签名 | `AGL-E-0319` |
| 每个签名必须有同文件实现 | `AGL-E-0320`，并给出「补函数 / 删签名」两条路 |
| 参数个数、参数名、参数类型、返回类型逐项一致 | `AGL-E-0321`，指出第一处不一致 |

接口是**纯编译期契约**：运行期不产生任何代码，IR 里只留一份签名记录，
Python 产物与没有接口时完全一致。`导出 接口` 让契约随模块一起导出；
导入方按接口逐项检查调用点仍是下一批（见 P6 待做）。

### 3.5 依赖声明（`依赖` / `deps`）

```agl
#语言=中文
依赖 {
  工具包 = "1.2.0"
  协议库 = "0.3.1"
}
```

| 规则 | 违反时 |
|---|---|
| 版本号必须写成字符串（`1.2.0` 会被词法拆成三个数字） | 解析期报 `AGL-E-0605` |
| 版本必须形如 `major.minor.patch` | `AGL-E-0605`，指出写法 |
| 同一个包只能声明一次 | `AGL-E-0307` |
| 包名是作者起的名字，转换时一个字都不动 | `依赖` ↔ `deps` 只换关键字 |

`dependencies` 只写进 IR，运行期不产生代码；没有依赖时 IR 里不出现该字段。
源码 `依赖` 块会与 `agl.toml [dependencies]` 对齐：配置里缺包或版本不一致 → `AGL-E-0605`；
配置里有、源码没声明仍放行（兼容既有工程）。真实版本解析仍是下一批。

### 3.5.1 可空类型与赋值 / 返回约束

```agl
#语言=中文
函数 可能空(有没有: 布尔) -> 文本? {
  如果 有没有 { 返回 "有值" }
  返回 空
}

函数 主入口() {
  变量 甲: 文本? = 空       // 合法：可空位置可以收 `空`
  变量 乙: 文本? = "AGL"    // 合法：普通文本可以进可空位置
  变量 丙: 文本 = 甲        // 报 AGL-E-0301：可空值不能流进非可空位置
}
```

| 位置 | 规则 | 违反时 |
|---|---|---|
| 变量声明 / 重新赋值 | 普通值可进可空类型；`空` 只能进 `T?`；`T?` 的值不能流进 `T` | `AGL-E-0301` |
| 函数返回 | 显式写了 `-> T?` 才收 `空`；`-> T` 返回 `空` 或 `T?` 值直接拒绝 | `AGL-E-0301` |
| 函数实参 | 与参数类型同规则（`T?` 参数收 `空`，`T` 参数不收） | `AGL-E-0301` |
| 比较 | `x 等于 空` / `x 不等于 空` 仍然永远允许，用于判空 | — |

当前只做「赋值 / 返回 / 实参」的类型兼容，不做跨分支的流敏感收窄：`如果 甲 等于 空 { … } 否则 { 甲.长度 }` 的 `否则` 分支仍把 `甲` 当作 `文本?`，需要显式转成非空值（如先 `变量 非空: 文本 = 取到(...)` 或重新赋一个非空值）。这条边界写在文档里，不假装已经做了数据流分析。

### 3.6 声明式块（`工具` / `智能体` / `规则`，阶段 2）

```agl
#语言=中文
工具 读取文件 {
  入参(文件路径: 文本)
  返回 文本?
  配置 {
    协议 = "mcp"
    地址 = "http://127.0.0.1:8080/mcp"
    最大重试次数 = 2
    超时秒数 = 10
    权限 = ["文件只读"]
    订阅 = 假
  }
}

规则 数据脱敏 {
  版本 = 2
  生效范围 = 全项目
  优先级 = 高
  内容 = "输出任何文本前先脱敏手机号与身份证号"
}
```

| 规则 | 违反时 |
|---|---|
| 工具协议只能是 `mcp` / `local-skill` / `acp`；`mcp` / `acp` 必须给地址 | `AGL-E-0605` |
| 配置字段只认 `协议 / 地址 / 最大重试次数 / 超时秒数 / 权限 / 订阅 / 模型 / 最大轮数`（英文同构） | `AGL-E-0605` |
| 智能体 `目标` 必须是非空字符串，`最大轮数` 必须是正整数 | `AGL-E-0605` |
| 规则 `版本 / 生效范围 / 优先级 / 内容` 必填；范围是 `全项目 / 模块 X / 目标 X`；优先级是 `高 / 普通 / 低`；`过期时间` 必须 `YYYY-MM-DD` | `AGL-E-0605` |
| 声明名与函数或其他声明重名 | `AGL-E-0605`（`DUP_DECL`） |
| 五个声明词与 `入参 / 配置` 仍保持 `stage = 2`，按源码原文识别，不占用普通标识符空间 | `input(...)` 这类同名内建调用不受影响 |

声明块是**纯编译期契约**：IR 里留 `declarations` 记录，运行期不产生代码；自举侧按花括号深度整块跳过。
`工具` 目前只做语法 + 静态校验，尚未真连 MCP。

### 3.7 重复调用熔断：设计占位（T19，未实现运行期代码）

**状态：只落设计，不落代码。** 当前 `工具` 声明不产生运行期代码，也没有真实的 MCP 调用
出口，所以熔断没有可挂载的执行点；提前写一个“假熔断器”只会制造第二套语义。

#### 3.7.1 触发条件与计数口径

| 项 | 设计口径 |
|---|---|
| 调用指纹 | `(工具名, 规范化参数哈希)`；参数按 AGL 值的规范 JSON 编码后哈希，键顺序不影响指纹 |
| 重试 | 瞬断错误（超时 / 连接重置 / 5xx）按任务策略的“最大重试次数”（默认 2）静默重试；404 / 401 / 参数错误等确定性失败不重试 |
| 同一指纹硬拦截 | 该指纹重试耗尽后仍失败 → 同一任务内下一次相同指纹直接拒绝，返回“换工具 / 改参数 / 走写好的降级路径” |
| 工具级熔断 | 同一任务契约内同一工具累计失败达到“熔断阈值”（默认 3）→ 熔断该工具，门禁级拒绝，直到任务契约结束 |
| 清零 | 同一任务内该工具成功调用一次，失败计数清零；新任务契约开始，指纹与工具计数全部重置 |
| 降级失败 | 任务代码 `try/except` 里写的降级路径也失败 → 直接停下等人工，不再让模型自行找第三条路 |
| 不写死降级 | 运行时不内置“失败后调哪个备用接口 / 给什么默认值”；降级分支只由任务代码决定 |

阈值全部来自任务策略块，语言只提供默认值，不把某个业务场景的策略写死进运行时。

#### 3.7.2 未来的挂载点（等真实工具执行落地）

1. `工具` 声明接入 MCP / local-skill / acp 的真实调用器时，在**统一调用分发器**入口建立
   指纹和计数；所有工具调用必须经过它，不能各后端各记一套。
2. 熔断状态挂在**任务契约**生命周期上，而不是进程全局；任务结束释放，避免跨任务污染。
3. 拒绝时返回结构化结果（`结果` 的失败分支），携带 `指纹 / 已失败次数 / 阈值 / 建议动作`，
   由任务代码的 `try/except` 接管；门禁级拒绝不能降级成普通异常被静默吞掉。
4. doctor 增加一组“假工具连续失败”用例：同一指纹第 3 次被拦、成功一次后计数清零、
   跨任务重置；用例只走假工具，不依赖外网。

#### 3.7.3 明确不做

- 不在 VM 里对普通函数调用做熔断；熔断只针对**外部工具调用**。
- 不把“连续失败”做成全局黑名单；不同任务、不同参数指纹互不影响。
- 不在本轮写任何计数器 / 错误码；等真实调用器与拒绝结果格式确定后一起落。

## 5. 改代码的标准流程（SOP）

任何改动，按这个顺序做，不许跳步：

```
1. 跑基线     python -m compiler.cli doctor        ← 必须先是全绿，否则先修基线
2. 改实现     只改 compiler/ 下你要改的那一层
3. 跑体检     python -m compiler.cli doctor
4. 看红了哪项 §4 的表里找到对应项 → 定位到具体文件
5. 有意改动？ 逐条确认差异是"你想要的"，再 python -m compiler.cli doctor --update-golden
6. 再跑一次   doctor 必须全绿
7. 交付       报告改了什么、哪项体检证明它没坏
```

**第 5 步是唯一允许刷新期望产物的时机，且必须能解释每一条差异。**
"跑一下 update-golden 就绿了"——这是作弊，不是修复。

### 5.1 加一个新语法特性，按这个顺序

以"加 `匹配`（match）"为例：

1. **`spec/keywords.toml`** — 确认关键字在，`stage` 改成 1（或保持 2）
2. **`spec/ir-schema.json`** — 加 `StmtMatch` 定义，挂到 `Stmt.oneOf`
3. **`compiler/parser/`** — 加 `parse_match()`，接进 `parse_stmt` 的分派
4. **`compiler/checker/`** — 加分支作用域检查和穷尽性检查
5. **`compiler/backend_py/`** — 加降级（`匹配` → if-elif 链）
6. **`tests/golden/`** — 加中英各一个用例
7. **`tests/cases/`** — 加至少一个错误用例（比如漏了 `_` 兜底）
8. **`tests/cases/expect.toml`** — 登记期望错误码
9. **`doctor --update-golden`** → **`doctor`** 全绿
10. **`docs/标准与契约.md` §8** — 更新能力边界表

**顺序不能乱**：契约（1-2）→ 实现（3-5）→ 用例（6-8）→ 固化（9-10）。
反过来做（先写实现再补契约）必然导致契约和实现对不上。

## 7. 中文分词规则（M1 的核心假设）

汉字连写没有空格，所以关键字和标识符会粘在一起。规则如下：

**位置敏感 + 最长前缀**：

| 位置 | 行为 | 例子 |
|---|---|---|
| 语句起始（行首、`{`、`}` 之后） | 整串先查**内建名**，命中（`失败原因`、`当前时间戳`）直接整体作标识符；否则按最长关键字前缀切开 | `失败原因(转整数("x"))` 的 `失败原因` 不切；`变量和 = 1` → `变量` + `和` |
| 表达式位置（已有 token 之后） | 整串要么是关键字，要么整体是标识符 | `变量 函数名 = 1` 里的 `函数名` 不切 |

英文分支不做前缀切分（`ifx` 是一个标识符，不是 `if` + `x`）。

**全角符号会自动归一**（`（` `）` `，` `：` 等 → 半角），字符串内不归一。

### 7.1 未启用的关键字不占用词汇（2026-10-27 决定）

`keywords.toml` 里 `stage > 1` 的词（`配置`、`入参`、`依赖`、`等待` 等），在阶段 1 **按普通标识符处理**：

```agl
变量 配置 = {"主机": "本地"}   // ✅ 合法：配置 是阶段 3 的词，现在不占位
```

理由：这些都是日常中文词。因为一个**尚未实现**的功能就禁止用户拿它当变量名，是不可接受的体验。
同理，混用检测（`AGL-E-0102`）也只对 `stage <= 1` 的词生效——否则英文分支里写
`let 配置 = …` 会被误报成"混用中文关键字"。

**代价（必须记住）**：将来启用这些词时，曾用它们作标识符的代码需要改名。
这是阶段 1 为了可用性做的主动取舍，不是疏忽。

### 7.2 `<` `>` 的歧义：泛型括号 vs 比较运算符（M6 转换器必须处理）

`List<Int>` 和 `n > 100` 用的是同一个符号。若转换器不区分，`List<Int>` 会被翻成
`列表小于整数大于` —— 这是实际踩到过的 bug。

处理方式：转换时维护**类型上下文**状态机。

| 触发 | 行为 |
|---|---|
| 遇到 `:`（参数类型）、`->`（返回类型） | 进入类型上下文，深度归零 |
| 类型上下文中遇到 `<` | 深度 +1，**该符号不转换** |
| 类型上下文中遇到 `>` 且深度 > 0 | 深度 −1，**该符号不转换** |
| 类型上下文中遇到 `{` `=` `)` `]` `}` `;`（深度 0）或换行 | 退出类型上下文 |
| 类型上下文中遇到 `,` 且深度 > 0 | 泛型参数分隔，保持上下文 |

实现位置：`compiler/convert.py` 的 `convert()`。
验证方式：`aglc roundtrip tests/golden/grammar_*.agl`（含 `List<Int>` 泛型）。

### 8.2 已明确不支持（会报错，不静默降级）

| 特性 | 现状 | 计划 |
|---|---|---|
| `匹配` match | **已实现**：语句版 `匹配 值 { … }`（括号可省略，也接受 `匹配 (值) { … }`），分支可写 `值 => 语句` / `{ … }`，否则兜底；表达式版 `变量 结果 = 匹配 主体 { 模式 => 表达式 … }`，分支体必须是单个表达式。模式支持字面量 / `_` / `变量 名` / 列表 / 映射 `{ "键": 模式 }` / 守卫 / `否则 如果`。重复字面量分支给 warning（`AGL-E-0317`）；真假值漏分支又没兜底也给 warning（`AGL-E-0318`） | 已是最终规则 |
| 条件类型 | `如果` / `当` 的条件必须是 `真假`（`结果` 也允许：成功为真、失败为假）；给数字 / 文本报 `AGL-E-0301`，不做隐式真值化 | 已是最终规则 |
| 入口函数签名 | `主入口` 不能带参数（`AGL-E-0313`）：程序起点没有调用方 | 已是最终规则 |
| 自定义类型 | 本文用 `类型 X { … }` 声明过的结构体名可作类型注解，声明顺序不限（支持前向引用、互相引用、自递归 `子: 列表<X>`）；构造时字段必须命名且按声明类型校验；同值结构体 `等于` 为真 | 结构体跨模块留待阶段 2 |
| 结构体字段名 | `长度` / `length` / `消息` / `message` 不能作字段名：它们是任何值上都有的保留属性，同名会与 `.长度`/`.消息` 二义（报 `AGL-E-0201`） | 已是最终规则 |
| `任务()` 参数 | 只接受异步调用（`睡眠(...)` / 异步函数）；传普通值报 `AGL-E-0315` | 已是最终规则 |
| 睡眠单位 | `睡眠(x)` 的 x 是**整数毫秒**；Python `time.sleep(0.5)` 导入为 `睡眠(取整(0.5 * 1000))`（亚毫秒截断，挂 warning） | 保持 |
| 跨类型比较 | `大于/小于` 系列：文本 vs 数字报 `AGL-E-0305`；`等于/不等于` 也查类别——文本×数字 / 真假×数字 / 真假×文本报 `AGL-E-0316`（空 与 类型未知 豁免：判空常用，不误报） | 阶段 3 类型推导加强后继续收紧 |
| 运行时沙箱 / 权限 / 配额 | **完全没有**：转出来就是普通 Python | 阶段 2 后端 B |
| 记忆外置 / 状态快照 / 回滚 | **完全没有** | 阶段 2 CVM |
| 类型推导 | 轻量，够抓 `"a" > 1` 这类明显错 | 逐步加强 |
| 属性访问（普通成员） | 原样转译（`x.状态` → `x.状态`）；若是 `类型` 声明过的结构体，编译期校验字段存在并给出字段类型；**结构体字段与 `.长度`/`.消息` 一律只读**，赋值报 `AGL-E-0303` | 已是最终规则 |
| 默认参数值 | 只能是字面量表达式（可含字面量之间的运算）；引用变量 / 调用函数报 `AGL-E-0301`——默认值在 `def` 时求值，早于顶层常量与运行时模板。**可变容器（`[]` / `{}` / 集合）不能做默认值**：默认值只求值一次会被所有调用共享，报 `AGL-E-0301`，改用 `空` + 函数体判空新建 | 已是最终规则 |
| 顶层常量初始化时机 | 生成代码里放到运行时模板之后、入口调用之前求值，因此可以调用内建、构造结构体 | 已是最终规则 |
| 优化 Pass | 默认关闭（`--opt` 可开） | 阶段 2 再评估是否默认开 |
| 标准库版本锁定 | `[dependencies]` 里的版本只记录不校验 | 标准库版本化之后启用 |
| 标准库覆盖 | 数学与列表聚合在标准库（`列表工具.求和` 等）；**内建函数优先**（`合计` / `绝对值` / `包含` / `切片` 等 29 个内建覆盖高频操作），两边职责不重叠 | 新增功能先进内建表 |

### 8.3 一句话说清安全边界

> **阶段 1 的安全 = 编译期声明校验**：不声明 `网络` 效应就编不过。
> **不是运行时强制**：转译出来的 Python 能干 Python 能干的一切。
> 沙箱、权限、配额、审批，全部属于阶段 2 后端 B。

任何对外表述都必须按这个口径，不许让读者以为 MVP 的 AGL 程序"默认被关在笼子里"。

## 9. 常见问题

**Q：为什么 AST 和 IR 要同构，不分开设计？**
A：分开就要维护两套结构 + 一个映射层，多一个必然出错的环节。同构的代价是 IR 里要能容忍语法糖（如 `匹配` 未降级），收益是少一层故障面。

**Q：为什么 `canonical` 只规范关键字，不规范标识符？**
A：关键字是语言骨架，必须跨分支一致；标识符是作者给的记号，翻译它会破坏可逆性，也让作者认不出自己的代码。这是 §3.17 的设计，不是偷懒。

**Q：中英两份文件为什么要各自手写，不用机器翻译？**
A：因为**填充内容不翻译**等于没起到翻译作用，而硬翻标识符必然破坏语义。真正的做法是：一个项目选定一种语言写，另一语言是给不同读者看的视图；逻辑等价由 IR 保证，由 `aglc compare` 验证。

**Q：为什么 `打印` 在 IR 里变成 `print`，而 `相加` 不变？**
A：`打印` 是内建（语言给的），必须跨分支一致；`相加` 是用户起的名，属于展示层。见 §2.3 的表。

**Q：`doctor` 第 10 项红了，但我觉得我的改动是对的，怎么办？**
A：先逐条看差异（`git diff tests/golden/`），确认每一条都是"我想要的"，再跑 `--update-golden`。如果解释不了某条差异，说明你有 bug，不是期望文件错了。

**Q：AI 客户端怎么用最省事？**
A：让它连 `agl-mcp`（`python -m compiler.mcp`，stdio）。握手时服务器会先告诉它
「写码前先调 `agl_card`」，之后 `agl_check` 返回的 `fix_hints` 里有 `at` 和 `suggest`，
AI 照着改就行。全程结构化 JSON，不需要它背命令、也不需要它背关键字表。

**Q：为什么优化必须默认关闭？**
A：阶段 1 的承诺是「AGL 第 N 行 = Python 第 N 行」，人审时才敢信行号。
优化会改写转译产物（常量变字面量、死代码消失），行号虽然还对得上，
但产物的形状不再和源码一一对应。所以它是 opt-in，而且必须过 `doctor` 第 15 项对拍。

**Q：契约层 `aglc/audit.py` 和编译器是什么关系？**
A：相互独立。契约层扫的是 **AI 写的 Python**，产出中文契约，让不懂代码的人也能看懂 AI 干了什么；它不依赖编译器，也不受编译器改动影响。0 token，纯本地静态分析。
