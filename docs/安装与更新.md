# AGL 安装与使用（2026-11-15 · v0.53.0）

> 仓库：https://github.com/SiyanHaven/AGL
> 普通用户装运行时包；开发 AGL 的人用源码树。两种形态分开，用户不需要看、也不需要改自举源码。

## 一、普通用户：在线安装

在任意目录执行；`:v0.53.0` 是发布标签，前提是该 Release 已上传 `agl_lang-0.53.0-py3-none-any.whl`：

```powershell
python -m pip install "https://github.com/SiyanHaven/AGL/releases/download/v0.53.0/agl_lang-0.53.0-py3-none-any.whl"
aglc doctor
```

只下载约 412 KB 的运行时 wheel，不 clone 仓库，也不下载自举源码、测试或编辑器扩展。不要用 `pip install git+https://...`：源码安装会先把整个仓库拉下来再构建。

期望输出：**5 项全部通过（运行时包）**。装完直接写 AGL：

```powershell
aglc init 我的Agent
aglc run 我的Agent/main.agl
```

用户包装了什么：

- `compiler/`、`aglc/`、`spec/`、`stdlib/`、`examples/`；
- `compiler/_runtime/自举编译器.agb`：预编译的编译引擎，705 KB 左右。

用户包**不含**自举源码、测试或编辑器扩展。`pip install` 不会下载这些内容；首次 `aglc run` / `aglc build` 不跑 40 秒自举链，只把内置 `.agb` 复制到用户目录（默认 `~/.agl/build/自举编译器/`，可用 `AGL_HOME` 改位置），不写 `site-packages`。

那个 `.agb` 不是让用户读的源码，是 `aglc` 编译 `.agl` 时要用的引擎文件。普通用户只写 `.agl`；自举源码只在 GitHub 源码仓库里，给开发者使用。

安装后 `aglc` 由当前 Python 的 `Scripts` 提供；MCP 直接启动，不需要源码目录：

```json
{
  "command": "python",
  "args": ["-m", "compiler.cli", "mcp"]
}
```

如果 agent 的 Python 不在 PATH，用该 Python 的绝对路径执行 `pip` 和 `aglc`。

## 二、开发者：源码树/完整自举

```powershell
git clone https://github.com/SiyanHaven/AGL.git
cd AGL
python -m compiler.cli doctor
```

期望输出：**5 项全部通过**。源码树形态提供编译器源码、自举源码和编辑器扩展，面向开发者；普通用户包不需要跑这套。

## 三、Release 压缩包（离线/普通用户）

把 `AGL-v0.53.0.zip` 解压到本机任意目录（下文记为 `<AGL 目录>`，不要求固定盘符），然后在该目录中执行：

```powershell
.\aglc.cmd doctor
```

期望输出：**5 项全部通过（运行时包）**。压缩包只含 `compiler/`、`aglc/`、`spec/`、`stdlib/`、`examples/`、`aglc.cmd` 和公开文档，不含测试、自举源码或编辑器扩展。`aglc.cmd` 自动设置 `PYTHONPATH`，从任何目录调用都不需要安装。

如果 `python` 不在 PATH，显式指定：

```powershell
$env:AGL_PYTHON = "<python.exe 的绝对路径>"
.\aglc.cmd info
```

## 四、三步跑起来

```powershell
mkdir 我的Agent
cd 我的Agent
python -m compiler.cli init .          # 或 aglc init .
python -m compiler.cli run main.agl    # 或 aglc run main.agl
```

`init` 之后目录长这样：

```
我的Agent/
├── agl.toml          # 项目配置（标准库依赖写这里）
├── main.agl          # 入口源码
├── 关键字速查.md      # 写码前读这一页
└── 写码须知.md
```

## 五、常用命令

| 命令 | 用途 |
|---|---|
| `aglc init <目录>` | 生成能直接跑的工程骨架 |
| `aglc run <文件.agl>` | 默认用自举编译器编译并交给 VM 执行，运行错误回译到 AGL 行号；也可直接 `aglc run <文件.agb>`；`--compiler seed` 回退 Python 种子 |
| `aglc check <文件> [--json]` | 只检查不产出；`--json` 给 AI 用 |
| `aglc build <文件>` | 默认自举编译器产出 `<名>.agb` 与 `<名>.agl.ir`（不再产出 `.py`）；依赖模块也落 `.agb`；`--compiler seed` 回退 |
| `aglc run <文件> --timeout-ms 5000` | VM 墙钟超时；默认不限，超时报 `AGL-RT-0095` |
| `aglc format <文件>` | 统一缩进、引号、空行 |
| `aglc lint <文件>` | 未使用变量、命名等问题 |
| `aglc summary <文件>` | 生成中文摘要（给不看代码的人） |
| `aglc card` | 输出关键字速查卡 |
| `aglc list-builtins` | 列出全部 187 个内建函数 |
| `aglc lsp` | 启动语言服务器（编辑器用） |
| `aglc mcp` | 启动 MCP 工具服务器（给 AI 客户端连） |
| `aglc doctor` | 自检：用户包与源码树均为 5 项 |
| `aglc clean` | 清理 `.agl.ir` / `__pycache__` |

**看帮助**：`aglc <命令> --help`。

### 桌面版

双击发布目录里的 `AGL编译器.exe`。它是一个 .NET WinForms 宿主，编译/运行仍走 AGL 的
AGB/VM；`python` 只负责启动编译器进程。桌面版默认用 PATH 里的 `python`，找不到时读取同目录的 `python-path.txt`，或认 `AGL_PYTHON`；发布包本身不带 Python，也不需要用户先 `pip install`。

如果窗口输出区提示「未找到 Python」，让 agent 做一件事即可：

```powershell
# 在 AGL 程序目录（AGL编译器.exe 所在目录）中执行
python -c "import sys,pathlib;pathlib.Path('python-path.txt').write_text(sys.executable, encoding='utf-8')"
```

然后重新打开 `AGL编译器.exe`。桌面版「编译」会生成 `.agb` / `.agl.ir`，
「运行」会直接显示程序输出；`Ctrl+B` / `Ctrl+R` 是同一动作的快捷键。

## 六、编辑器

用户包不含编辑器扩展。需要语法高亮时，从源码仓库单独下载 VS Code 扩展。

### VS Code

1. 把源码仓库中的 VS Code 扩展目录复制到
   `%USERPROFILE%\.vscode\extensions\agl-language-0.4.0\`（按扩展的安装方式安装）；
2. 重载窗口，`.agl` 文件即有语法高亮；
3. 语言服务：扩展会调用 `python -m compiler.lsp`。装了 `aglc` 之后任何项目都能用；
   如果 Python 不在 PATH，在设置里填 `agl.pythonPath`（值为 Python 可执行文件的完整路径）。

### 其它编辑器

`aglc grammar --dir <目录>` 生成 TextMate 语法文件，可接到任何支持 TextMate 的编辑器。

## 七、MCP（AI 客户端）

当前 MCP 事实（与 `compiler/mcp.py` 一致，版本跟随 `spec/keywords.toml`）：

- 服务器：`agl-mcp`
- 版本：**0.53.0**
- 协议：**2024-11-05**
- 工具数量：**10**

工具清单：`agl_card`、`agl_check`、`agl_check_source`、`agl_build`、`agl_run`、`agl_run_source`、
`agl_convert`、`agl_summary`、`agl_version`、`agl_doctor`。

先自检：

```powershell
python -m compiler.mcp --version
#   → agl-mcp 0.53.0（协议 2024-11-05）
python -m compiler.mcp --list
#   → 10 个工具清单
```

在线 pip 安装后，直接启动控制台脚本，不需要 `cwd`：

```jsonc
{
  "command": "aglc",
  "args": ["mcp"]
}
```

压缩包形态则指向解压目录：

```jsonc
{
  "command": "python",
  "args": ["-m", "compiler.cli", "mcp"],
  "cwd": "<AGL 目录>"
}
```

`cwd` 填本机实际解压/克隆的目录即可，不要求某个固定盘符。

## 八、更新

在线安装升级到新标签：

```powershell
python -m pip install --upgrade --force-reinstall "https://github.com/SiyanHaven/AGL/releases/download/v0.54.0/agl_lang-0.54.0-py3-none-any.whl"
aglc doctor                      # 用户包 5/5 才算更新成功
```

源码树/压缩包在 `<AGL 目录>` 中执行：

```powershell
git pull                         # 或下载新版覆盖（不要覆盖已有文件）
python -m compiler.cli doctor    # 源码树 5/5 才算更新成功
```

MCP 是客户端拉起的子进程，长连接不会自动加载新代码：**重启/重连客户端**即可。

## 九、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `ModuleNotFoundError: compiler` | 没在发布包根目录运行，或 `PYTHONPATH` 没指向该目录；在 `<AGL 目录>` 中用 `.\aglc.cmd`，或直接 `python -m compiler.cli` |
| `aglc` 不是命令 | 在线安装没进当前 Python 的 `Scripts`；用安装时的同一个 Python 执行 `python -m pip install ...`，或直接用 `python -m compiler.cli` |
| 运行报 `AGL-RT-0095` | 触发墙钟超时；加终止条件，或显式调大 `--timeout-ms` |
| 运行报 `AGL-RT-0091` | 触发步数上限；加终止条件，或显式调大 `--max-steps` |
| 编辑器没有诊断 | 语言服务没起来；看 VS Code「输出 → AGL」，设 `agl.pythonPath` |
| `aglc doctor` 报某运行时项红 | 先看是否缺少 `AGL_HOME` 写权限；用户包与源码树均应 5/5 |
