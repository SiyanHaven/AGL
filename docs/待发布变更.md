## 2026-11-22：MCP 的 stdio 传输

工具运行时原先只支持 MCP 的 Streamable HTTP，而本地 MCP 服务器（filesystem、sqlite、
git 之类）几乎都只提供 stdio。现在补上 stdio：

- `传输 = "stdio"` + `命令`（命令行文本或字符串数组），`地址` 不再要求；
- 一行一条 JSON-RPC 消息的帧，`initialize` → `notifications/initialized` → `tools/call`，
  一次调用起一个子进程，用完关掉；
- 结果解析、瞬断重试、指纹与熔断全部复用 HTTP 版同一套；
- `工作目录` 可指定子进程工作目录，默认继承当前进程；
- stderr 直接丢弃，避免服务器日志把管道写满；
- 编译期拦住三种歧义：stdio 缺 `命令`、`传输` 值不是 http/stdio、非 mcp 协议写 `传输`。

### 相关实现

- `compiler/backend_py/__init__.py`：新增 `_agl_tool_transport`、`_agl_mcp_command_spec`、
  `_agl_mcp_result_text`（HTTP 与 stdio 共用解析）与 `_agl_call_tool_mcp_stdio`；
- `compiler/parser/__init__.py`：配置块字段表新增 `传输 / 命令 / 工作目录`；
- `compiler/checker/__init__.py`：传输值、命令形态与「stdio 必须有命令」的校验；
- `tests/mcp/stdio_server.py`：自检用的假 stdio 服务器；
- `tests/suite/checks.py`：新增第 16 项「MCP stdio 传输」；
- `docs/标准与契约.md`：配置字段表更新，新增 3.6.2 传输契约。

- VM：同一份 `.agb` 输出与 Python 后端逐字相同；
- CLI 默认（自举）路径：`aglc run --allow-effects External --allow-tools 天气` 输出
  `上海：晴，23度`；
- `命令` 写成字符串数组时同样跑通；

### 已知边界

- 不支持 stdio 的长连接复用：每次调用重新起进程、重新握手；
- 不做 `tools/list` 缓存，工具名由声明决定，不与服务器清单比对；
- stderr 被丢弃，服务器自己的诊断信息不会进 AGL 报错，只保留 JSON-RPC 的 error 字段。

## 2026-11-22：本地技能协议（`协议 = "local-skill"`）

工具运行时之前只认 MCP 的 Streamable HTTP；校验器虽然接受 `local-skill`，运行期却直接拒绝。
现在这条协议补上了，语义是「调用本机一个技能目录里的可执行入口」：

- `地址` 是技能目录，目录里一般有 `SKILL.md` 与入口脚本；
- `入口` 是新增的配置字段（如 `入口 = "run.py"`），省略时按
  `run.py` / `main.py` / `run.cmd` / `run.bat` / `run.ps1` 依次探测；
- 每次调用起一个子进程，工作目录为技能目录，环境里额外给 `AGL_TOOL_NAME` 与 `AGL_SKILL_DIR`；
- 请求走 stdin 的一行 JSON：`{"tool": 工具名, "arguments": 实参映射表, "config": 配置映射表}`；
- 退出码 `0` 视为成功，stdout 是 JSON 就解析成 AGL 值，否则按纯文本返回；
- 非零退出码是确定性失败，不重试，报错带 stderr 末尾 300 字；
- 超时杀掉子进程并按瞬断处理，走现有 `最大重试次数` 与熔断逻辑；
- 指纹、重试与熔断和 MCP 共用同一套状态，所以两种协议的工具混用也不会各记一套。

`acp` 仍未实现，调用时给出明确说明，不再笼统地说「只支持 mcp」。

### 相关实现

- `compiler/backend_py/__init__.py`：`_agl_call_tool` 拆成分发器 + `_agl_call_tool_mcp`
  + `_agl_call_tool_local`，新增 `_agl_local_skill_entry` / `_agl_local_skill_command`；
- `compiler/parser/__init__.py`：配置块字段表新增 `入口 / entry`；
- `compiler/checker/__init__.py`：`local-skill` 也要求 `地址`；`入口` 只允许出现在该协议；
- `tests/skills/示例技能`（含 `SKILL.md` + `run.py`）与 `tests/skills/失败技能/run.py`：
  给自检用的最小技能包；
- `tests/suite/checks.py`：新增第 15 项「本地技能协议」；
- `docs/标准与契约.md`：3.6 配置字段表与新增 3.6.1 本地技能协议契约。

### 验证记录

- Python 后端：`求和(2, 3)` 返回映射表，输出 `5` 与工具名；
- VM：同一份 `.agb` 输出与 Python 后端逐字相同；
- CLI 默认（自举）路径：`aglc run --allow-effects External --allow-tools 求和` 输出 `15`；

### 已知边界

- 每次调用起一个进程，没有常驻技能进程池，冷启动开销按宿主解释器算；
- 不解析 `SKILL.md`，说明文件只给人读，运行期不据此推断能力；
- 不做技能目录的路径白名单，`地址` 写哪儿就能跑哪儿的脚本——调用方自行保证来源可信。


## 2026-11-16：可编程网页应用

### 新增语言能力

`启动网页应用(端口, 处理函数名, 绑定地址?)`（英文 `web_serve`）：

- 效应为 `网络`，由 VM 和 Python 种子后端共同实现；
- 绑定地址可省略，默认 `127.0.0.1`（只接受本机访问）；需要局域网访问时显式传
  `"0.0.0.0"`，并自行考虑鉴权；
- 每个 HTTP 请求构造一个请求映射表，交给同模块中指定名称的 AGL 函数；
- 处理函数返回响应映射表，也允许直接返回文本；
- 支持 `GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `HEAD`，`OPTIONS` 由运行时处理；
- 内置表单解析、JSON 序列化、CORS、`Content-Length` 和统一 `500` 异常响应；
- 返回映射表或列表时默认使用 `application/json`。

请求映射表：

| 键 | 含义 |
|---|---|
| `方法` | HTTP 方法 |
| `路径` | 解码后的路径 |
| `原始路径` | 带查询串的原始请求行 |
| `查询` | 查询参数映射表，同名参数取最后一个值 |
| `查询串` | 原始查询串 |
| `Cookie` | Cookie 请求头解析后的键值映射表 |
| `请求体` | 请求体原文 |
| `表单` | `application/x-www-form-urlencoded` 表单字段 |
| `头` | 请求头映射表 |
| `内容类型` | `Content-Type` |

响应映射表：

| 键 | 含义 |
|---|---|
| `状态` | HTTP 状态码，默认 `200` |
| `类型` | `Content-Type`；不写时自动判断 |
| `内容` | 文本，或自动序列化的映射表 / 列表 |
| `文件` | 要返回的文件路径，按二进制读取并自动推断 MIME |
| `头` | 额外响应头 |

### 相关实现

- `compiler/webapp.py`：可编程 HTTP 服务运行时，标准库实现，无第三方依赖；
- `compiler/vm.py`：VM 侧内建注册与处理函数调用；
- `compiler/backend_py/__init__.py`：Python 种子后端内建；
- `spec/keywords.toml`：新增 `启动网页应用` / `web_serve` 规格；
- `自举/内建表.agl` 与 `自举/字节码.agl`：自举侧内建表与规范名映射；
- `docs/网页应用.md`：请求 / 响应契约与完整案例说明；
- `docs/标准与契约.md`：服务内建一行同步更新。

### 新增示例

## 2026-11-17：安全默认与审计修复

第三方审计针对公开仓库旧 HEAD `1851991`，其中几项与本地当前代码直接相关，已先修：

- **网页服务默认回环**：`compiler/webapp.py`、VM `_agl_web_serve`、种子后端
  `_agl_启动网页应用` 统一默认 `127.0.0.1`；旧的 `启动HTTP` / `启动待办Web`
  也不再默认绑定 `0.0.0.0`。`启动网页应用` 增加可选第三参 `绑定地址`，

- **待办 HTML 转义**：种子后端的待办页把数据库内容经 f-string 直插 HTML，
  现改为 `html.escape(str(...))`，修掉存储型 XSS。
- **获取网页协议限制**：只允许 `http` / `https`，拒绝 `file://` 等协议，
  避免直接读本机文件；没有做私网地址封禁，SSRF 风险仍需调用方自行控制。
- **BOM 兼容**：`compiler/cli/pipeline.py`、CLI 源文件读取、`modules.py`、
  `mcp.py` 的源码读取改为 `utf-8-sig`；带 UTF-8 BOM 的 AGL 源文件不再报
  “缺少语言声明”。

- **MCP 路径边界（部分）**：`compiler/mcp.py` 的 `_file` 与 `agl_build` 的 `out_dir`
  现在必须落在工作区内，默认工作区是启动服务器时的当前目录；需要更大范围时
  显式设置 `AGL_MCP_WORKSPACE`。`tool_run` 对 `.agb` 的效应/工具授权默认值
  仍未收紧，属于下一项。

  `--allow-effects External`。
- **重复调用熔断（T19）**：统一工具调用器 `_agl_call_tool` 按 `(工具名, 规范化实参)`
  计算 SHA-256 指纹。瞬断错误（超时 / 连接重置 / 5xx / 429）按 `最大重试次数`
