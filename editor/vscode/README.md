# AGL 编辑器扩展（VSCode）

语法高亮 + 语言服务。**零 npm 依赖，不需要 `npm install`** —— 装上就能用。

## 它做什么

| 能力 | 前置条件 | 说明 |
|---|---|---|
| 语法高亮 | 无 | 中英两分支关键字、运算符词、内置属性、字符串、注释、首行语言声明 |
| 诊断 | 需要 Python + 能定位到 aglc | 边打字边检查，错误按 AGL 行号标出，附带修复建议 |
| 悬停 | 同上 | 关键字给出中英对照与阶段；函数给出完整签名与效应 |
| 补全 | 同上 | 当前分支关键字、本文件函数；`. ` 之后只给内置只读属性 |
| 大纲 | 同上 | 本文件的函数列表 |
| 跳转 | 同上 | 从调用处跳到函数定义 |

**找不到编译器时不会报错**：自动降级为「只有高亮」，并在右下角状态栏写明原因。
高亮永远可用，所以哪怕只想要上色，装它也够了。

## 安装

扩展不需要编译、不需要打包，直接放进扩展目录即可。

### 方式一：直接拷进扩展目录（推荐，一次就完）

在 AGL 目录中执行：

```bash
# Windows
xcopy /E /I editor\vscode %USERPROFILE%\.vscode\extensions\agl-language-0.4.0

# macOS / Linux
cp -r editor/vscode ~/.vscode/extensions/agl-language-0.4.0
```

重启 VSCode，打开任意 `.agl` 文件即生效。

### 方式二：调试运行（改扩展本身时用）

用 VSCode 打开 `editor/vscode` 目录，按 `F5`，会起一个加载了本扩展的新窗口。

## 语言服务怎么找到编译器

按顺序找 `compiler/lsp.py`：

1. 当前工作区目录（含各层父目录，最多往上 12 层）；
2. 当前打开的 `.agl` 文件所在目录往上找；
3. 扩展自己所在目录往上找。

找到就用它启动 `python -m compiler.lsp`。找不到时：
- 状态栏显示「AGL：仅高亮」；
- 输出面板（`AGL`）里写明原因；
- 可以把扩展放在 AGL 仓库的 `editor/` 下，或在设置里指路。

### 设置项

| 设置 | 默认 | 用途 |
|---|---|---|
| `agl.pythonPath` | `python` | 跑语言服务的解释器。`python` 不在 PATH 时填绝对路径 |
| `agl.serverModule` | `compiler.lsp` | 语言服务模块名，一般不用改 |

## 已知边界

- **只支持全量同步**：每次修改都把整份文件推给服务器。文件都在几百行内，速度无感；
  真遇到大文件卡顿再改成增量同步。
- **不做格式化、不做重命名**：这两件事要在 IR 上做，排在阶段 2 之后。
- **不检查运行时**：诊断只覆盖编译期（词法 / 语法 / 语义 / 效应 / 模块）。
  想跑程序用 `aglc run` 或 MCP 工具。
- **中英混写会在编辑器里报错**：这是语言规则（AGL-E-0102），不是扩展的毛病。
  一个文件只用一种分支的关键字。

## 语法高亮是生成的，不要手改

`syntaxes/agl.tmLanguage.json` 由 `spec/keywords.toml` 生成：

```bash
python -m compiler.cli grammar --dir editor/vscode
```

改关键字请改表，然后重新生成。`aglc doctor` 会检查两件事：
表里每个启用的词都能被高亮规则匹配上；磁盘上的文件与重新生成的结果逐字相同。
所以「表里加了词、高亮漏了」这种漂移会在体检时就红掉。
